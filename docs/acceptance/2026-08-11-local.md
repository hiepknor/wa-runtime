# Local staging acceptance — 2026-08-11

## Scope

This acceptance run exercised the Docker Compose deployment as a staging-like local environment.
It used the single allowlisted development session and local PostgreSQL, Redis and OpenWA services.
It is not evidence for a separately operated production host or production credentials.

Safety conditions before the run:

- `.env` had `ALLOW_LIVE_SENDS=false`;
- `GET /api/v1/health/ready` independently reported `liveSendsEnabled=false`;
- OpenWA release `0.15.0` matched the configured pin;
- exactly one session was allowlisted;
- all acceptance deliveries used `DRY_RUN`.

The integration harness separately exercised the complete `LIVE` message processor against fake
OpenWA with outbound delay set to zero. It created 500 distinct recipients and used two independent
`QueueService` instances to model competing worker replicas.

| Measurement | Result |

| Total fake-OpenWA send calls | 500 |
| Durable `ACCEPTED` jobs / attempts | 500 / 500 |
| Duplicate recipients / attempts | 0 / 0 |

This is evidence for Runtime locking, classification and persistence behavior only. Fake OpenWA did
not contact WhatsApp and does not establish a safe production send rate.

## Remaining production gates

- Repeat this run on the actual staging host with production-like network latency and data volume.
- Establish an operational monitoring approach before enabling production live sends.
