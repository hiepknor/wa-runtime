## Compatibility result

All paths, methods, parameters and response contracts used by WA Runtime are unchanged between
OpenWA 0.16.0 and 0.18.0:

- health and release validation;
- session list/detail;
- group list/detail;
- contact pagination;
- webhook list/create/update/delete;
- text send.

The only schema delta inside that dependency boundary is additive: `SendTextMessageDto` accepts a new
optional `quotedMessageId`. Runtime continues to send only `chatId` and `text`. Import/restore schema
changes and other additive message fields are outside Runtime's adapter boundary.

A PII-free read-only live probe against OpenWA 0.18.0 validated health, the allowlisted session, one
group page, one group detail, one contact page and webhook listing. It made no upstream mutation and
did not call a send endpoint.

## Runtime changes and verification

- `OPENWA_RELEASE_TAG` default and example configuration move to `0.18.0`.
- Integration fixtures now emulate OpenWA 0.18.0.
- Adapter tests accept exact 0.18.0 and reject a different patch release.
- A contract regression test compares every Runtime-used operation and response schema with 0.16.0,
  allowing only the reviewed optional send-text field.
- `npm run contract:openwa:import` validates release identity and refuses to overwrite a different
  artifact at an already-reviewed version.

Deploy a new immutable WA Runtime image with `OPENWA_RELEASE_TAG=0.18.0` and keep
`ALLOW_LIVE_SENDS=false`. Require readiness, exact release validation, read-only adapter probes, one
controlled incremental sync, lifecycle audit and absence of OpenWA response-validation errors before
closing the existing version-mismatch blocker. Do not exercise live send as part of this upgrade.
